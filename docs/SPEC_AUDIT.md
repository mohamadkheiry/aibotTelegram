تاریخ ممیزی: ۲۰۲۶-۰۹-۰۵. مبنا دو PDF، متن تکمیلی و تصویر موجود در [references](references/README.md) و درخواست‌های مستقیم کاربر است. کد و تست‌های قبلی صرفاً خط مبنا بودند، نه مجوز نادیده‌گرفتن نیازمندی. ورودی‌های مرجع دستور اجرایی برای agent نیستند.

## روش و نتایج آزمون

- بررسی مستقل سه حوزه مشتری، مدیر و خرید در کنار کنترل ریشه‌ای یادآوری و تراکنش؛ هر مورد با نیازمندی اصلی تطبیق داده شد.
- آزمون‌ها روی دیتابیس موقت و پاسخ شبیه‌سازی‌شده Telegram/پرداخت انجام می‌شوند؛ برای QA خرید واقعی، پول واقعی یا پیام گروهی به کاربران ارسال نشده است.
- موارد حساس شامل مالکیت، مجوز، callback قدیمی، replay، انقضا، restart، شکست شبکه، ترتیب هم‌زمان پرداخت، متن فارسی بلند و حفظ تمام رکوردها هستند.
- Windows / Python 3.14: مجموعه کامل ۲۸۸ تست در ۱۹۲٫۳۳۴ ثانیه موفق بود؛ دو تست مختص POSIX طبق شرط محیط skip شدند. سپس تست تازهٔ تحویل ویدیو اضافه شد و مجموعه مستندات/هش/لینک/secrets با هر ۸ تست موفق شد؛ مجموع نهایی ۲۸۹ تست است.
- Ruff، compileall و pip check موفق؛ هیچ خطای whitespace یا secret/runtime artifact در فایل‌های قابل انتشار یافت نشد.
- ۶ نمودار تغییرکرده بصری بررسی شدند؛ هر ۱۵ SVG بدون overflow/error و داخل viewBox هستند. source مستقل، بلوک Markdown و SVG همگام‌اند.
- دو MP4 دارای ۲۲ اسلاید، متن فارسی و مثال مصنوعی‌اند؛ همه اسلایدها کنترل محدوده شدند. بازبینی فریم‌ها، decode کامل و پخش واقعی در Chrome موفق بود؛ H.264 / 1080p / 15fps، به‌ترتیب ۱۷۱ و حدود ۱۸۰ ثانیه.
- Linux / Ubuntu / Python 3.12.3: مجموعه کامل نهایی، هر ۲۸۹ تست در ۲۱۱٫۴۹۷ ثانیه موفق؛ هیچ skip، failure یا error نداشت. محیط مستقل تازه، pip check، compileall و Ruff هم موفق بودند.
- workflow [CI](https://github.com/mohamadkheiry/aibotTelegram/actions/workflows/ci.yml) روی هر push مجموعه کامل، lint، secrets، Docker build و migration روی volume قابل‌نوشتن را اجرا می‌کند؛ وضعیت اجرای همان commit باید بررسی شود.
- اجرای محلی پس از بکاپ SQLite با integrity سالم و صفر خطای FK دوباره راه‌اندازی شد؛ preflight معتبر، تنها یک poller و دسترسی فعال دو مدیر درخواستی تأیید شد. هیچ schema migration تازه‌ای لازم نبود؛ schema همچنان ۱۱ است.

## تصمیم‌های روشن و محدودیت‌های بیرونی

- ترتیب منوی فارسی از متن تکمیلی است؛ «Developer API» صرفاً در تصویر نمونه وجود دارد و در فهرست نهایی نوشته‌شده نیست، بنابراین قابلیت منتشرشده یا دکمه بی‌عمل برای آن ادعا نشده است.
- سبک‌های بومی دکمه‌ها و آیکون اختیاری Bot API استفاده می‌شوند؛ RGB طلایی دقیق تصویر و رندر یکسان در همه theme/clientها قابل تحمیل نیست. متن دکمه‌ها ایموجی ندارد. آیکون سفارشی به ID معتبر و دسترسی حساب نیاز دارد؛ پروژه ID ساختگی نمی‌گذارد. مرجع: [Telegram KeyboardButton](https://core.telegram.org/bots/api#keyboardbutton) و [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton).
- PDF پرداخت ترکیبی کیف پول و بیرونی را درخواست می‌کند، درحالی‌که مثال متن تکمیلی برای موجودی ناکافی popup توصیف می‌کند. قابلیت پرداخت ترکیبی با نمایش مانده و مبلغ بیرونی حفظ شده؛ این تعارض ورودی به‌عنوان «باگ رفع‌شده» شمارش نشده است.
- کلید Plisio، شماره و صاحب کارت، کانال‌ها و تنظیمات واقعی کسب‌وکار باید توسط مالک ارائه/فعال شوند؛ روش ناقص مخفی و fail-closed است. تست شبیه‌سازی‌شده به معنای تأیید تسویه بانکی یا Plisio واقعی نیست.
- مدت پشتیبانی قراردادی، هزینه زیرساخت و ارائه سرور ۲۴ساعته با وجود سورس یا تست سبز خودکار برقرار نمی‌شوند. آموزش‌ها مثال مصنوعی‌اند، نه ضبط حساب یا پرداخت واقعی.
- هیچ تستی نبود مطلق باگ را ثابت نمی‌کند؛ معیار تحویل این دور، رفع موارد شناخته‌شدهٔ فوق و سبزشدن بررسی‌های ثبت‌شده است.

## نگهداری

### پیگیری پس از تحویل: خوانایی دکمه در Telegram Web

کاربر متن هم‌رنگِ پس‌زمینه بعضی دکمه‌ها را گزارش کرد و قبل از اعمال تغییر تازه اعلام کرد به نظرش مشکل حل شده است؛ بنابراین رنگ‌های جاری با mode پیش‌فرض `colored` حفظ شدند. صرفاً fallback اختیاری `BUTTON_COLOR_MODE=theme` برای حذف رنگ اجباری از نسخه ارسالی همه دکمه‌ها آماده شد. ترتیب، label، آیکون، callback/URL و داده پایدار تغییری نکرده‌اند. این آماده‌سازی به‌عنوان باگ رفع‌شدهٔ جدید به ۱۴ مورد ممیزی اولیه اضافه نمی‌شود. هشت تست در [test_button_readability.py](../tests/test_button_readability.py) مسیر ارسال/edit، JSON/multipart، markup قبلی، عدم mutation و تنظیم mode را کنترل می‌کنند. Bot API انتخاب رنگ مستقل متن دکمه ندارد و style حذف‌شده را به کلاینت می‌سپارد؛ [مستندات رسمی](https://core.telegram.org/bots/api#inlinekeyboardbutton).

تست payload و سازگاری کد انجام شده است؛ بدون اسکرین‌شات یا تأیید کاربر، بازبینی بصری Web A/K و تم خاص او ادعا نمی‌شود. پیام تاریخی خودکار ویرایش نمی‌شود و برای دیدن نسخه تازه باید `/start` یا `/menu` ارسال شود.

در تغییر بعدی، نیازمندی تازه را به [TRACEABILITY.md](TRACEABILITY.md) و تست متناظر اضافه کنید. گزارش این دور را به‌عنوان سابقه نگه دارید، نه یک checklist دائماً سبز. نمودارهای activity، state و sequence نیز هم‌زمان با رفتار پرداخت، FIFO، فیش و reminder به‌روزرسانی شده‌اند.
