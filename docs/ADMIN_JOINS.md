# مدیریت دکمه‌ای جوین اجباری

درخواست مستقیم کاربر در 2026-09-05: در بخش جوین اجباری، هر کانال یک دکمه با نشان فعال/غیرفعال ✅/❌ داشته باشد؛ افزودن و بازگشت زیر فهرست باشند و هر کانال صفحهٔ مستقل با تغییر وضعیت، حذف و بازگشت داشته باشد. این سند مکمل [ساختار ۹بخشی](ADMIN_HIERARCHY.md) و [قرارداد فرم‌ها](BUTTON_UI.md) است.

## مسیر و دکمه‌ها

«پنل مدیریت ← مدیریت کلی ربات ← جوین اجباری»:

- برای هر کانال: «✅ نام کانال» اگر فعال و «❌ نام کانال» اگر غیرفعال؛
- «افزودن کانال اجباری»؛
- «بازگشت» به مدیریت کلی ربات.

در فهرست بیش از ۲۰ کانال، «صفحه قبل/بعد» فقط به‌قدر نیاز اضافه می‌شوند. همه کانال‌ها، فعال و غیرفعال، با ترتیب ثابت sort_order/id و total دقیق قابل پیمایش‌اند. فهرست خالی فقط توضیح نبود کانال، افزودن و بازگشت دارد.

پس از انتخاب یک کانال، نام، شناسه، آدرس و وضعیت فعلی نمایش داده می‌شود و دقیقاً سه دکمه وجود دارد:

1. «فعال/غیرفعال کردن»؛
2. «حذف»؛
3. «بازگشت» به همان صفحه فهرست.

تغییر وضعیت و حذف، فرم تأیید کانال انتخاب‌شده را باز می‌کنند؛ کانال دوباره پرسیده نمی‌شود. لغو به همان کانال برمی‌گردد. پس از تغییر وضعیت، بازگشت وضعیت جدید را نشان می‌دهد؛ پس از حذف، مقصد فهرست است و صفحه خارج از محدوده به آخرین صفحه معتبر محدود می‌شود. دکمهٔ کانال حذف‌شده، فهرست تازه را نشان می‌دهد و روی کانال دیگری عمل نمی‌کند.

افزودن همان فرم سه‌مرحله‌ای فعلی است: یوزرنیم/شناسه کانال، عنوان، لینک عضویت و تأیید نهایی. قبل از افزودن یا فعال‌سازی، Bot API باید channel/supergroupبودن مقصد و مدیر بودن ربات را تأیید کند. خطای سرویس یا نبود مجوز، هیچ کانالی را فعال نمی‌کند. کانال موجود با همان شناسه مطابق رفتار قبلی upsert می‌شود؛ افزودن کانال تکراری رکورد دوم نمی‌سازد.

## استثنای محدود علامت وضعیت

خواستهٔ جدید کاربر فقط برای پیشوند وضعیتِ دکمهٔ کانال‌ها بر سیاست قبلی «بدون Unicode emoji» مقدم است. `force_join_channel_button` عنوان plain را با validator موجود می‌سازد و فقط یک ✅ یا ❌ ثابت به آن می‌افزاید. emoji موجود در عنوان ورودی پاک می‌شود؛ `callback_button`، `reply_button` و منوی مشتری همچنان emoji در label ورودی را رد می‌کنند. از این استثنا برای تزئین سایر دکمه‌ها استفاده نکنید. رنگ‌ها و تنظیم `BUTTON_COLOR_MODE` تغییر نکرده‌اند.

## قرارداد پیاده‌سازی و بازیابی

- `app/admin_joins.py`: مرور خواندنی فهرست و کانال، page/context، احراز نقش زنده و بازکردن فرم مشترک؛ بدون SQL mutation جدید.
- state مرور `admin:joins` شامل scope=joins، kind=list/channel، id اختیاری، page، actor/chat و prompt_message_id است.
- فرم `admin:ui` دارای `return_to.scope=joins` و minimum_step است؛ return_route به `j:back` می‌رود و فرم‌های محصول بدون scope جدید همچنان `c:back` را دارند.
- callbackهای `adm:ui:j:*` فقط صفحه/فرم را باز می‌کنند. شناسه پایدار، نه index فهرست، در callback است. mutation همچنان token/revision، تأیید، journal و handler موجود دارد.
- private chat و نقش owner/admin در هر ورودی و پیش از mutation بررسی می‌شود. support و نقش لغوشده به این بخش دسترسی ندارند.
- keyboard قبلی با edit markup بازنشسته می‌شود؛ failure پاک‌سازی مانع guardهای idempotency نیست. restart، replay و فرم قدیمی نباید toggle دوم یا حذف اشتباه ایجاد کنند.
- فرمان‌های joins/join_add/join_toggle/join_delete برای سازگاری باقی‌اند. دکمه‌های عملیات پراکنده از صفحه تنظیمات حذف و با یک ورودی «جوین اجباری» جایگزین شده‌اند؛ پنل اصلی همچنان ۹ بخش دارد.

## آزمون پذیرش

اجرای هدفمند 2026-09-05: هر ۲۸ تست این بخش و سازنده‌های keyboard موفق شدند. lint/compile و ۸ تست سلامت اسناد/منابع/لینک‌ها و secret scan نیز موفق‌اند. نمودار جدید و نمودار اجزا رندر و بازبینی شدند؛ اسلاید تنظیمات به‌روز، کنترل بیرون‌زدگی، decode کامل و پخش مرورگری ویدیوی آموزش موفق بود.

۱۳ تست اختصاصی در `tests/test_admin_joins.py` از keyboard/message ID واقعاً ارسال‌شده به FakeTelegram استفاده می‌کنند: فهرست خالی، وضعیت فعال/غیرفعال، صفحه سه‌دکمه‌ای، افزودن مجاز/نامجاز، target ثابت، دوبار تأیید، لغو/حذف، صفحه دوم، حذف هم‌زمان/تغییر ترتیب، private chat، revoke، payload نامعتبر، restart، crash پس از commit toggle یا پیام و محدودبودن emoji به پیشوند کانال. اعتبارسنجی شبکه در تست‌ها fake است؛ هیچ کانال واقعی اضافه/حذف یا poller دوم اجرا نمی‌شود.

```bash
python -m unittest tests.test_admin_joins tests.test_keyboards -v
python -m unittest discover -s tests -v
python -m ruff check .
```

نتیجه دقیق suite کامل در CI همان commit ثبت می‌شود. نمودار فعالیت: [۱۸ در DIAGRAMS.md](DIAGRAMS.md). استقرار بدون migration/schema جدید است؛ backup، توقف نمونه قبلی و start تک‌نمونه‌ای در [deployment.md](deployment.md) رعایت شود. کانال‌ها، وضعیت آن‌ها و داده production با این rollout تغییر نمی‌کنند. پس از rollout از `/start` و مسیر بالا استفاده کنید؛ هنگام rollback به نسخه قدیمی نیز `/start` state جدید را کنار می‌گذارد.
